# 동해 서프 월드

동해안 해변 다섯 곳(속초, 양양, 강릉, 포항, 부산)을 골라서, 실제로 접속한 사람들과 함께 파도를 타고 채팅하는 웹 서비스입니다. Node.js 서버 하나가 웹페이지와 실시간 접속(WebSocket)을 함께 처리합니다.

## 구성

| 파일 | 역할 |
|---|---|
| `server.js` | 웹페이지 제공, 해변별 방과 채널 운영, 파도 생성, 위치 중계, 채팅 |
| `public/index.html` | 게임 화면 전체(3D 장면, 로비, HUD, 채팅) |
| `Dockerfile` | 컨테이너로 배포할 때 사용합니다 |

## 로컬에서 실행하기

Node.js 18 이상이 필요합니다.

```bash
npm install
npm start
```

브라우저에서 `http://localhost:8080` 을 엽니다. 다른 브라우저 창을 하나 더 열면 두 사람이 같은 바다에 있는 상태를 확인할 수 있습니다.

## 배포하기

WebSocket을 지원하는 Node.js 호스팅이면 어디든 배포할 수 있습니다. 대표적인 방법은 다음과 같습니다.

- **Render, Railway 같은 PaaS:** 저장소를 연결하고 시작 명령을 `npm start` 로 지정합니다. 포트는 플랫폼이 넣어 주는 `PORT` 환경 변수를 그대로 사용합니다.
- **Fly.io, Cloud Run, 쿠버네티스 같은 컨테이너 환경:** 포함된 `Dockerfile` 로 이미지를 만들어 배포합니다. Cloud Run에서는 요청 제한 시간을 늘리고 세션 어피니티를 켜야 WebSocket 연결이 오래 유지됩니다.
- **직접 운영하는 서버(VPS):** `npm ci --omit=dev` 후 pm2나 systemd로 `node server.js` 를 실행하고, 앞단의 nginx에서 아래처럼 WebSocket 업그레이드를 넘겨줍니다.

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 3600s;
}
```

HTTPS로 배포하면 클라이언트가 자동으로 `wss://`(암호화된 WebSocket)로 접속합니다. 웹페이지와 서버를 다른 도메인에 따로 올리는 경우에는 `index.html` 의 첫 `<script>` 앞에 `<script>window.SURF_WS='wss://서버주소/ws'</script>` 를 넣어 접속 주소를 지정합니다.

### 환경 변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `8080` | 서버 포트 |
| `MAX_PER_CHANNEL` | `40` | 한 채널의 최대 인원입니다. 넘으면 2채널, 3채널이 자동으로 열립니다 |
| `MAX_CONN_PER_IP` | `6` | IP 하나에서 동시에 열 수 있는 연결 수 |
| `TRUST_PROXY` | 없음 | 프록시나 로드밸런서 뒤에서 실행할 때 `1` 로 지정하면, `X-Forwarded-For` 헤더로 실제 IP를 판단합니다 |

### 상태 확인 주소

- `GET /healthz` 는 `ok` 를 돌려줍니다. 플랫폼의 헬스 체크 경로로 지정하면 됩니다.
- `GET /api/rooms` 는 해변별 현재 접속자 수를 JSON으로 돌려줍니다.

## 동작 방식

- **방과 채널:** 해변마다 방이 따로 있고, 한 채널이 가득 차면 다음 채널이 자동으로 열립니다. 사람이 모두 나가면 그 채널은 정리됩니다.
- **파도 동기화:** 서버는 파도가 생긴 시각, 크기, 부서지기 시작하는 지점(봉우리)만 정합니다. 각 브라우저는 서버 시각을 기준으로 같은 공식을 계산하므로, 모든 접속자가 같은 자리의 파도를 봅니다. 파도를 먼저 잡으려고 패들한 사람이 그 파도의 봉우리 위치를 정합니다.
- **위치 중계:** 각 브라우저는 0.1초마다 자기 위치와 동작을 보내고, 서버는 0.1초마다 방 전체 상태를 한 번에 묶어서 보냅니다.
- **채팅:** 메시지는 120자까지 보낼 수 있습니다. 10초에 5개, 0.7초에 1개까지만 받고, 기본적인 욕설은 `*` 로 가립니다. 보낸 메시지는 채팅창과 캐릭터 머리 위 말풍선에 함께 표시됩니다.
- **연습 모드:** 서버에 연결되지 않으면(예: 파일로 직접 열었을 때) 컴퓨터가 움직이는 서퍼와 함께 혼자 타는 연습 모드로 들어갑니다. 이때는 채팅이 꺼집니다.

## 실제 서비스 전에 확인할 것

- **서버 한 대 기준 설계:** 방 정보가 서버 메모리에 있습니다. 서버를 여러 대로 늘리려면 같은 해변의 접속자를 같은 서버로 보내는 라우팅이나, Redis 같은 공유 저장소가 필요합니다.
- **신고와 차단:** 지금은 금칙어를 가리는 기능만 있습니다. 공개 서비스라면 신고, 사용자 차단, 운영자 알림 기능을 추가하고, 금칙어 목록(`server.js` 의 `BAD_WORDS`)을 보강하는 것이 좋습니다.
- **로그인 없음:** 이름은 접속할 때마다 자동으로 만들어지고 따로 저장하지 않습니다. 기록은 각 브라우저에만 저장됩니다.
- **값과 공식 일치:** `server.js` 의 `SPOTS` 값과 파도 속도 공식은 `public/index.html` 의 값과 같아야 합니다. 한쪽을 고치면 다른 쪽도 함께 고쳐 주세요.
- **외부 자원:** three.js는 CDN에서 먼저 불러오고, 실패하면 서버의 `/three.min.js` 를 사용합니다. 글꼴은 Google Fonts에서 불러옵니다.
